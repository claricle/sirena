== Purpose

Sirena is a pure Ruby interpreter of commonly-used diagram generation languages
into SVG format.

Sirena currently supports the following diagram definition syntaxes:

// * PlantUML - the text-based UML diagramming language defined by PlantUML
* Mermaid - the text-based diagramming language defined in mermaid-js

Sirena aims to provide high compatibility with the original tools while offering
a pure Ruby implementation that can be easily integrated into Ruby-based
workflows and tools.

NOTE: The name "Sirena" is derived from "Siren", a mythological creature known
for its enchanting songs that lure sailors, as its usage in multiple languages
refer to mermaids.

== Implementation notes

The library follows strict object-oriented principles with a model-driven
architecture. Most diagram models use `Lutaml::Model`, but not all data
structures do: `Sirena::Diagram::TreemapNode` and `Sirena::Diagram::RadarAxis`
are plain Ruby classes, and the transform/layout pipeline between parsing and
rendering passes plain hashes rather than typed models. The pipeline keeps a
clean separation between parsing, transformation, layout, and rendering
phases.


== Features

=== Diagram language support

Mermaid defines a set of diagram type languages for composing different diagram
types.

Sirena registers 24 diagram types. 23 are Mermaid input languages; the 24th is
`error`, the fallback Mermaid.js renders when its own parsing fails. Mermaid's
ZenUML is not registered. Per-type compatibility with real Mermaid.js input
varies (see below).

=== Mermaid diagram types

Sirena registers 24 Mermaid diagram types end-to-end (parser, transform, and
renderer). Registration is not the same as full compatibility: measured
per-type pass rates against the mermaid-js corpus range from 66.7% to 100%
and are documented on the
https://claricle.github.io/sirena/pages/compatibility/[compatibility page]
and in `scoreboard/corpus.json`.

* **Flowchart** - Directional graphs with various node shapes and edge types
* **Sequence diagram** - Message flows between participants over time
* **Class diagram** - UML class relationships and hierarchies
* **State diagram** - State machine transitions and hierarchies
* **Entity-relationship diagram** - Database schema relationships
* **User journey** - User interaction flows with satisfaction levels
* **Gantt chart** - Project timelines and task dependencies
* **Pie chart** - Proportional data visualization
* **Quadrant chart** - 2D data point categorization
* **Requirement diagram** - Requirements and their relationships
* **Git graph** - Git branching and commit history
* **Mindmap** - Hierarchical mind mapping
* **Timeline** - Event sequences over time
* **Sankey diagram** - Flow quantities between nodes
* **XY chart** - Line and bar charts with axes
* **Block diagram** - Block-based architecture diagrams
* **Packet diagram** - Network packet structure
* **C4 diagram** - Software architecture contexts and containers
* **Architecture diagram** - Service and component architecture
* **Kanban board** - Workflow status tracking
* **Radar chart** - Multi-dimensional data comparison
* **Treemap** - Hierarchical data as nested rectangles
* **Error diagram** - Error message display
* **Info diagram** - Information display

See link:examples/README.adoc[] for working examples of all diagram types.

=== Core capabilities

* **Pure Ruby implementation** - No JavaScript dependencies
* **Parslet-based parsing** - Superior error messages and maintainability
* **SVG output** - Standards-compliant SVG 1.2
* **Theme support** - 4 built-in themes, custom theme support
* **Auto-detection** - Automatic diagram type detection
* **Batch processing** - Process multiple diagrams at once
* **CLI tool** - Command-line interface for standalone usage
* **Programmatic API** - Ruby library for custom workflows
* **Metanorma-oriented SVG** - Self-contained SVG for embedding in Metanorma
  documents; flowchart, sequence, class, pie and Gantt renders pass
  `svg_conform`'s `:metanorma` conformance check with zero errors (checked
  directly against `SvgConform.validate`; `spec/svg_conformance_spec.rb`
  runs this on every suite run against shipped examples, reference
  fixtures, and the mermaid corpus)

== Installation

=== Via RubyGems

Add Sirena to your Gemfile:

[source,ruby]
----
gem 'sirena'
----

Then execute:

[source,shell]
----
bundle install
----

Or install it directly:

[source,shell]
----
gem install sirena
----

=== Requirements

Ruby 3.2 or higher.


== Quick start

=== Command-line usage

Render a single Mermaid diagram to SVG:

[source,shell]
----
sirena render diagram.mmd -o output.svg
----

Render all Mermaid files in a directory:

[source,shell]
----
sirena batch -i input_dir/ -o output_dir/
----

List all supported diagram types:

[source,shell]
----
sirena types
----

=== Programmatic usage

Use Sirena in your Ruby code:

[source,ruby]
----
require 'sirena'

# Render from a string
mermaid_code = <<~MERMAID
  graph TD
    A[Start] --> B[Process]
    B --> C[End]
MERMAID

svg = Sirena.render(mermaid_code)
File.write('output.svg', svg)

# Render from a file
svg = Sirena.render(File.read('diagram.mmd'))
File.write('output.svg', svg)

# Pick a built-in theme
svg = Sirena.render(mermaid_code, theme: 'dark')
----

== Architecture

=== General

Sirena implements a pipeline architecture that transforms Mermaid source
code through distinct processing stages, each with clear responsibilities and
well-defined interfaces.

**All parsers use Parslet**, a powerful PEG (Parsing Expression Grammar) library
that provides superior error messages, composability, and maintainability
compared to traditional lexer-based approaches. The 3-layer Parslet architecture
(Grammar → Transform → Parser) is not universal: 10 of the 23 builders subclass
`Parslet::Transform`, the rest are plain classes, and User Journey builds its
model directly in the parser.

Layout currently uses a built-in fallback grid (`Layout::Grid`, see the TODO in
`Engine#layout_graph`); the
elkrb gem is a declared dependency but is not called yet. Sirena is a pure Ruby
implementation with no JavaScript dependencies, generating standards-compliant
SVG 1.2 output suitable for direct integration with Metanorma documentation
frameworks.

   │   Model   │  (Flowchart, Sequence, etc.)

         │
         ▼
   ┌───────────┐
   │Transform  │  Diagram → Graph Conversion
   │  Layer    │
   └─────┬─────┘
         │
         ▼
   ┌───────────┐

=== Parslet-based parser architecture

All 24 implemented diagram types use Parslet for grammar parsing, but only 10 of
the 23 builders subclass `Parslet::Transform`. Where the 3-layer pattern is
followed it looks like this:

. **Layer 1: Grammar** (Parslet::Parser) - Defines syntax rules using Parslet
  DSL, parses text into intermediate tree structures
. **Layer 2: Transform** (Parslet::Transform) - Converts intermediate trees to
  typed Diagram models using pattern matching
. **Layer 3: Parser** - Orchestrates Grammar and Transform, provides public API

Several types deviate: `lib/sirena/parser/builders/architecture.rb` and
`lib/sirena/parser/builders/class_diagram.rb` (among other builders under
`lib/sirena/parser/builders/`) are plain Ruby classes rather than
`Parslet::Transform` subclasses, and `Sirena::Parser::UserJourney#parse`
builds its diagram model directly from the parse tree without a separate
Transform layer.

This architecture provides:

* **Superior error messages** with detailed context and line numbers
* **Composability** through shared grammar rules across diagram types
* **Maintainability** via declarative, self-documenting syntax rules
* **Type safety** through strongly-typed Lutaml::Model objects

See link:ARCHITECTURE.md[] for detailed architecture documentation.

== Test coverage

=== General

Sirena's test suite exercises the extracted mermaid-js corpus (`spec/mermaid/`)
across all registered diagram types. The `mermaid:validate` rake task
(`lib/tasks/generate_mermaid_fixtures.rake`) checks only that
`Sirena.render` runs without raising on each corpus source; it does not
compare output against mermaid-cli reference SVGs. Comparison against
mermaid-cli-generated reference output is a separate, optional task
(`rake mermaid:compare`, not run in CI or the default suite) — see
"Mermaid-js compatibility validation" below.

=== Mermaid-js compatibility validation

Sirena's test suite includes test cases that covers all diagram types to ensure
comprehensive compatibility and correctness.

`spec/fixtures_mermaid/` contains 847 unique mmdc-generated reference SVGs
(each duplicated into a `correct/` subdirectory, so a naive file count reads
~1,694); no automated spec currently compares rendered output against them.
