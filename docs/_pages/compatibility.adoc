== Sirena vs Mermaid.js Compatibility

=== Purpose

This page focuses specifically on **Mermaid.js syntax compatibility** - what works, what differs, and how to migrate. For a broader comparison with other diagram tools (PlantUML, Graphviz), see link:../comparison/[Tool Comparison].

=== Overview

Sirena reads Mermaid.js syntax in a pure Ruby implementation. This page documents measured compatibility and known differences between Sirena and Mermaid.js.

==== Not Supported

* **ZenUML** - Not implemented. Mermaid publishes a syntax reference at
  https://mermaid.js.org/syntax/zenuml; use `sequenceDiagram` instead.

=== Syntax Compatibility

==== Shared Syntax

The following syntax elements exist in both Mermaid.js and Sirena; exact
parity has not been verified element-by-element and is not claimed:

* Diagram type declarations
* Node definitions
* Edge/relationship definitions
* Labels and text
* Subgraphs and grouping
* Comments (`%%`)
* Title and accessibility attributes

==== Minor Differences

===== Styling

**Mermaid.js:**
[source,mermaid]
----
graph TD
    A[Node]
    style A fill:#f9f,stroke:#333,stroke-width:4px
----

**Sirena:**
Inline `style` lines are accepted by the parser but have no effect on the output (measured: the node keeps the theme fill and stroke). Apply a theme globally instead:
[source,bash]
----
sirena render diagram.mmd --theme dark
----

===== Click Events

**Mermaid.js:** Supports click events and callbacks
[source,mermaid]
----
graph TD
    A[Node]
    click A callback "Tooltip"
----

**Sirena:** `click` lines are accepted and ignored; no link or callback is emitted (static SVG output)

===== Custom CSS Classes

**Mermaid.js:** Supports CSS class assignment
[source,mermaid]
----
graph TD
    A[Node]
    class A myClass
----

**Sirena:** `class` and `classDef` lines are accepted and ignored; use the theme system for styling

=== Performance Comparison

The `benchmark:compare` and `benchmark:quick` rake tasks run against
`Sirena.render`. One dated Apple M2 comparison with mermaid-cli, its method,
and reproduction commands is published in the
link:../../performance-benchmark/[Performance Benchmark report]. That report did
not measure memory, and one machine's result is not a general performance
guarantee. Sirena's lack of a browser or Node.js dependency remains a
structural difference, not itself a timing measurement.

=== Migration Benefits

==== Why Migrate to Sirena?

**Simpler Deployment**

* No Node.js required
* No headless browser (Puppeteer/Chrome)
* Single Ruby gem installation

**No Browser Dependency**

* No headless browser or Node.js runtime to run
* The recorded benchmark is scoped to one machine and contains no memory
  measurement (see Performance Comparison above)

**Ruby Ecosystem**

* Rake task automation ships today (`tasks/*.rake`)
* Rails helpers/views and Jekyll-specific integration are not built; using
  Sirena from a Rails or Jekyll app today means calling `Sirena.render`
  yourself, the same as from any other Ruby code

**Enhanced Tooling**

* Built-in batch processor
* YAML-based themes
* Command-line tools

=== Not Migrating? When to Use Each

==== Use Mermaid.js When:

* You need interactive diagrams in browser
* You need click events and callbacks
* You have complex custom styling
* You're already using Node.js stack
* You need real-time client-side rendering

==== Use Sirena When:

* Server-side rendering is required
* Building Ruby applications that can call `Sirena.render` directly
* Batch processing many diagrams
* CI/CD diagram generation
* Simpler deployment is priority

=== Compatibility Testing

Compatibility can be checked with:

[source,bash]
----
# Run Mermaid.js compatibility tests
rake mermaid:validate

# Compare output with Mermaid.js
sirena render diagram.mmd -o sirena-output.svg
# Compare with mermaid-cli output
----

=== Future Compatibility

Sirena aims for syntax parity with Mermaid.js; the table above is the measured state. New Mermaid.js features will be evaluated for inclusion based on:

* Server-side rendering applicability
* Ruby ecosystem fit
* Performance impact
* Community demand
